这个博客的第四次重写，终于停在了静态站点上。

前三次分别是 WordPress、自建 Next.js、以及一个用 Docker 跑起来的 Ghost。每一次我都觉得自己找到了终极方案，每一次都在半年后开始后悔。

## 前三次是怎么失败的

**WordPress（2018）**：插件装了 23 个，其中 11 个常年不更新。某天凌晨被扫出一个漏洞，数据库被塞了垃圾评论。修了两天，决定搬走。

**Next.js 自建（2021）**：一开始很爽，SSR、ISR、各种新概念。半年后发现：为了写一篇文章，我要改三个配置文件；部署依赖一个每月 20 美元的服务器；某次依赖升级直接让构建挂了三天。

**Ghost + Docker（2023）**：Ghost 本身很好，但它假设你需要一个「内容团队」。会员、订阅、邮件、主题市场——我一个写随笔的人，用不上这些。最后为了省内存，还给它调了半天容器限制。

三次失败的共同点：**我在为一个「可能的未来」付维护成本。** 那个未来（百万读者、内容团队、付费订阅）从来没有发生。

## 静态站到底解决了什么

现在这套是 Astro 构建的纯静态站。文章是 `src/content/blog/` 下的 Markdown 文件，构建后生成 HTML，扔到任何静态托管上。

它解决的不是性能问题（虽然 Lighthouse 确实接近满分），而是三件更实际的事：

### 1. 零维护

没有数据库要备份，没有服务器要打补丁，没有运行时依赖要升级。唯一的依赖是构建工具，而它只在本地跑。

### 2. 内容永不过期

Markdown 文件是人类可读的纯文本。十年后，就算 Astro 不存在了，随便一个编辑器都能打开它。而数据库里的一篇文章，换个系统就得写迁移脚本。

### 3. 部署是原子的

一次构建产出一个完整的 `dist/` 目录。要回滚？切回上一个构建产物就行，不用考虑数据库 schema 是否兼容。

## 代价是什么

诚实地说，静态站也有代价：

| 能力 | 静态站方案 |
| --- | --- |
| 评论 | 只能用第三方（Giscus 之类），或多一个后端 |
| 搜索 | 客户端搜索，全量索引不能太大 |
| 草稿预览 | 需要在本地跑构建 |
| 动态功能 | 基本别想 |

对我这种写作频率（每月 2–4 篇）来说，这些代价都可以接受。**如果你的站点每天要发几十篇、需要实时评论和个性化推荐，那静态站不适合你。**

技术选型的第一步不是选最好的，是选**和你真实使用强度匹配的**。

## 现在这套的具体数字

- 首屏 HTML + CSS：约 30 KB（gzip 后）
- 构建时间：40 篇以内，约 3 秒
- 托管成本：0 元（GitHub Pages）
- 依赖数量：5 个（Astro、MDX、RSS、Sitemap、Sharp）

对比一下 2021 年那套 Next.js：`node_modules` 有 800 多 MB，首屏 JS 有 400 KB。

## 折腾的意义

有人会问：花这么多时间折腾博客系统，值吗？

如果只看「写文章」这个目标，不值。用任何一个现成平台，五分钟就能开始写。

但对我个人来说，每次重写都是一次练习：重新想清楚「我到底需要什么」。前三次失败的原因，都是我在为想象中的需求做设计。

第四次终于想明白了：**我不需要内容管理系统，我需要一个能存放文字的地方。**

这个结论花了八年。
