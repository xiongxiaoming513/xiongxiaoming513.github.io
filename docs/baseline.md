# 基线表（个人博客版）

> 目的：90 天后能回答一个问题——**这套 AI 工作流到底有没有效。**
> 规则：每个需求一行，交付当天记；每月底汇总。数据来自 git、GitHub Actions 和会话记录，不追求精确，只要求能对比。

## 一、指标定义

| # | 指标 | 定义 | 采集方式 |
| --- | --- | --- | --- |
| 1 | 交付时长 | 从提出需求到上线（或合并到 main） | 会话时间 + 提交时间 |
| 2 | 人介入次数 | 需求之外需要我澄清、确认、返工的次数（纯验收不算） | 人工记 |
| 3 | AI 首次成功率 | 不需要返工且不需要额外澄清就达成的需求占比 | 由下表统计 |
| 4 | 返工次数 | 交付后因质量问题再次修改的次数 | git / 人工记 |
| 5 | 验证耗时 | `make verify` 的实际耗时 | 实测 |
| 6 | 部署耗时 | push 到线上可访问 | GitHub Actions |
| 7 | 线上缺陷 | 上线后发现的错误（内容错、断链、样式崩） | 冒烟 + 人工发现 |
| 8 | Token 成本 | 本周期 API 花费（可选，个人项目按月） | 账单 |

## 六、怎么更新这张表

```bash
# 提交数与时间线
git log --pretty=format:'%h | %ad | %s' --date=format:'%m-%d %H:%M'

# 验证耗时（应稳定在 3 秒内，变慢说明环境在腐化）
/usr/bin/time -p make verify

# 最近部署耗时
gh run list --workflow=deploy.yml --limit 5
```

每月底花 10 分钟：把新需求补进台账，汇总到第四节，更新第二节的基线数字。
